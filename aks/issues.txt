I am unable to connect the aks cluster like not able to run kubectl get nodes
 command or any other because cluster is having Azure AD RBAC enabled so you need 
 an Azure role assignment to access the cluster. Let's fix this. 

ISSUES:

$ kubectl get nodes
Error from server (Forbidden): nodes is forbidden: User "p.kumari@slalom.com" cannot list 
resource "nodes" in API group "" at the cluster scope: User does not have access to the 
resource in Azure. Update role assignment to allow access.

##Resolution:
Why This Happens
Your AKS cluster uses Azure AD RBAC (azure_rbac_enabled = true in the module). This means every user needs an Azure RBAC role on the AKS cluster to access it — even you who created it.

✅ Fix: Assign Yourself the Cluster Admin Role
Step 1: Get your Azure AD Object ID

az ad signed-in-user show --query id --output tsv

This will print something like: a1b2c3d4-e5f6-7890-abcd-ef1234567890

Step 2: Assign the Cluster Admin role

az role assignment create \
  --assignee "$(az ad signed-in-user show --query id --output tsv)" \
  --role "Azure Kubernetes Service RBAC Cluster Admin" \
  --scope "/subscriptions/cad44ef1-313a-4da8-8d66-a58b6467472e/resourceGroups/rg-test-app/providers/Microsoft.ContainerService/managedClusters/aks-test-app"

  Step 3: Wait 1-2 minutes for role to propagate, then test

  Option B: Use Admin Credentials (Bypass Azure RBAC Temporarily)
  
  aks get-credentials --resource-group rg-test-app --name aks-test-app --admin

  This uses the local admin account instead of Azure AD. Then test:

  --admin bypasses RBAC — use only for testing, not production.
